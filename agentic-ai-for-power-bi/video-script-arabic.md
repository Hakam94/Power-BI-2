#### 📌 التغيير الأول: Agent Skills for Power BI

**[شرح بطيء، مع أمثلة عملية]**

> الميزة الأولى اسمها **Agent Skills for Power BI** — وهي في Preview الحين.
>
> تخيّل إنك تقول للـ AI:
> "ابني لي موديل بيانات لمبيعات شركتي، مع تقرير يبين الأداء الشهري، وKPIs للمناطق الجغرافية."
>
> والـ Agent يروح ويسوي:
> - ينشئ الجداول والعلاقات في الـ Semantic Model
> - يكتب الـ DAX Measures اللازمة
> - يبني صفحات التقرير
> - يختار الـ Visuals المناسبة بناءً على best practices
> - وينشر كل شي في الـ Fabric Workspace
>
> كيف يصير هذا؟ من خلال شي اسمه **Power BI Authoring Plugin** — حزمة أدوات موجودة في **Skills for Fabric Marketplace**. هذه الحزمة تتضمن MCP Servers — وهذا راح نشرحه بعد شوي.
>
> لكن المهم الحين: مش بس تقدر تعطيه تعليمات نصية. تقدر تحطله **screenshot** لتصميم تقرير تحبه، وهو يعيد إنشاؤه في Power BI. مباشرة.
>
> هذا بيغير كل شي لمحللي البيانات. المهارة اللي كانت تاخذ ساعات صارت تاخذ دقائق.

#### 📌 التغيير الثاني: Fabric Apps for Semantic Models

**[نبرة استعراضية]**

> الميزة الثانية اسمها **Fabric Apps for Semantic Models**.
>
> الفكرة بسيطة لكن قوية: تخيّل إن عندك Semantic Model كامل في Fabric — جداول، علاقات، مقاييس، كل شي — والحين تبي تبني تطبيق ويب كامل فوق هذا الموديل.
>
> قبل؟ كنت محتاج مطور Frontend، وBackend، وAPI، وDesigner. وكم أسبوع من الشغل.
>
> الحين؟ الـ Agent يبني لك تطبيق ويب **Fabric-native** مباشرة فوق الـ Semantic Model. بكلام طبيعي. وتنشره مباشرة في Fabric.
>
> يعني في أسبوع، تقدر تحوّل موديل بيانات لتطبيق إدارة مخزون، أو تطبيق تخطيط مالي، أو داشبورد تنفيذي — بدون فريق تطوير كامل.
>
> هذا تسريع هائل لدورة حياة المشاريع التحليلية.

### 🟣 [5:30 - 7:00] MCP — بروتوكول السياق النموذجي

**[نبرة تعليمية، شرح مفهوم تقني بأسلوب مبسط]**

> الحين خلينا نفهم الـ "How" — كيف يتواصل الـ Agent مع Power BI؟
>
> الجواب هو **MCP — Model Context Protocol**. بروتوكول السياق النموذجي.
>
> فكّر فيه زي **USB-C للذكاء الاصطناعي**. معيار موحّد يخلي أي Agent يتكلم مع أي نظام، بطريقة واحدة ومعيارية.
>
> Microsoft عندها الحين نوعين من MCP Servers لـ Power BI:
>
> **الأول: Remote Power BI MCP Server**
> هذا للتحليل والـ Insights. يخلي الـ Agent يتصل مباشرة بـ Semantic Models المنشورة في Fabric، يولّد DAX Queries، ويجاوب أسئلة بيانات — مع الحفاظ الكامل على صلاحيات الأمان Row-Level Security.
>
> **الثاني: Local Power BI Modeling MCP Server**
> هذا للتطوير والبناء. يشتغل محلياً على جهازك، يعطي الـ Agent صلاحية كاملة على ملفات الـ `.pbip` في Power BI Desktop. يقدر يسوي bulk operations — تغيير أسماء الكولمز، إنشاء Measures، بناء علاقات — كلها بكلام طبيعي.
>
> والجميل؟ MCP نفسه تطوّر. في يوليو 2026، البروتوكول انتقل لـ **Stateless Architecture** — يعني أسرع، أرخص، وأسهل في التوسع على مستوى المؤسسات.
>
> وعشان تجرّب: كل اللي تحتاجه هو إن Admin الـ Fabric يفعّل إعداد "Users can use the Power BI MCP server endpoint" — وبعدين تتصل من VS Code أو Claude Desktop أو أي Agent تختاره.

### 🟠 [7:00 - 8:15] Fabric IQ — طبقة الذكاء الدلالي

**[نبرة جادة، تعمّق في المفهوم الأساسي]**

> قبل ما نكمل، في مفهوم محوري لازم تفهمه: **Fabric IQ**.
>
> Fabric IQ هو الطبقة الذكية الأساسية في الـ Platform. فكّر فيه كـ "دماغ" يربط كل الـ Agents بسياق الأعمال الحقيقي.
>
> المشكلة اللي كانت موجودة: الـ AI بدون سياق يعطيك إجابات "ذكية" بس مش دقيقة — لأنه يخمّن على أساس أسماء الجداول مش على أساس المنطق التجاري الحقيقي.
>
> Fabric IQ يحل هذه المشكلة. كيف؟
> يوحّد **Metrics، Relationships، وDefinitions التجارية** في طبقة واحدة مشتركة بين كل الـ Agents. يعني كل Agent يشتغل على نفس "فهم" للأعمال — مش على تخمينات.
>
> وهو جزء من منظومة أكبر اسمها **Microsoft IQ**:
> - **Work IQ**: سياق من Microsoft 365 — إيميلات، اجتماعات، مستندات
> - **Fabric IQ**: سياق البيانات والمقاييس التجارية
> - **Foundry IQ**: المعرفة المؤسسية الموثّقة
>
> والنتيجة؟ Agents متعددة تقدر تشتغل مع بعض على بيانات مشتركة، موثوقة، ومحكومة — بدون تناقض أو أخطاء.
>
> Fabric IQ هو اللي يحوّل الـ Semantic Model من مجرد ملف Power BI إلى **Infrastructure استراتيجي** لكل الـ AI Agents في المؤسسة.

### 🔴 [8:15 - 9:15] التأثير على مستقبلك — ماذا يعني هذا عليك؟

**[نبرة صادقة، مباشرة، شخصية]**

> الحين، السؤال الأهم: ماذا يعني هذا التطور عليك كمحلل بيانات أو مطور Power BI؟
>
> خليني أكون صريح معك:
>
> **الأعمال المتكررة ستختفي.** كل اللي كان يأخذ ساعات من الـ Data Modeling والـ DAX الأساسي والـ Report Building — الـ Agents ستأخذه. هذا مش تهديد، هذا تحرير لوقتك لأشياء أهم.
>
> **الـ Semantic Model صار المهارة الأهم.** مش عارف DAX جيد؟ مش مشكلة والـ Agent يكتبه. لكن اللي يفهم **كيف يبني Semantic Model صحيح، منطقي، ومحكوم** — هذا هو اللي ستحتاجه المؤسسات. لأن الـ Agent اللي يشتغل على موديل رديء يعطيك إجابات رديئة. GIGO — Garbage In, Garbage Out.
>
> **دور المحلل يتطور، مش يختفي.** من تنفيذ مهام إلى **تحديد المشاكل، مراجعة نتائج الـ AI، وضمان الجودة**. القيمة المضافة الإنسانية انتقلت للمستوى الاستراتيجي.
>
> **الأمان والحوكمة صارت ميزة تنافسية.** المؤسسات اللي تبني Agents محكومة بـ Microsoft Purview وEntra ID — هذي هي اللي ستكسب. لأن الثقة في الـ AI مش بالمعجزات، بالحوكمة.
>
> المؤسسات اللي بدأت تجرّب هذه الأدوات شافت تخفيض يصل لـ 80% في وقت الأعمال المتكررة. هذا مش مبالغة — هذا ما تقوله أبحاث 2026.
